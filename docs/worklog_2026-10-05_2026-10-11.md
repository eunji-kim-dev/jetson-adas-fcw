  - 150프레임 모두 값 일치

## 4. INT8 MinMax 엔진 속도 비교

### 작업 내용
- 9/27에 만든 INT8 MinMax 엔진의 속도를 처음으로 측정함.
- FP16, INT8 Entropy, INT8 MinMax를 같은 조건에서 각각 3회씩 비교함.
- 720p 영상, GPU 전처리, 경고 규칙 비활성화 조건으로 측정함.

### 검증 결과

| 정밀도 | 처리 시간 | FP16 대비 |
|---|---:|---:|
| FP16 | 16.7ms | 기준 |
| INT8 Entropy | 13.6ms | 19% 감소 |
| INT8 MinMax | 14.0ms | 16% 감소 |

- INT8은 FP16보다 약 2.7~3.1ms 빨랐음.
- AI 추론 시간(Full+Crop)은 FP16 7.8ms에서 INT8 5.7~5.9ms로 줄어듦.
- 각 정밀도에서 3회 반복한 결과 차이는 0.1ms 이내였음.

### 알게 된 점
- INT8에서 추론 속도가 빨라지는 효과를 다시 확인함.
- 다만 AI 정밀도와 직접적인 관계가 없는 GPU 전처리 시간도 1.66ms에서 0.81ms로 줄어든 현상이 있었음. 원인은 아직 확인하지 못함.
- Entropy가 MinMax보다 조금 빠른 이유는 검출된 박스 수가 적기 때문일 가능성이 있음.

**최종 정밀도는 FP16을 유지함.**

INT8 MinMax는 검출률이 회복되었지만, 박스 좌표가 흔들리는 현상이 FCW 경고에 어떤 영향을 주는지 아직 검증하지 않았기 때문임.

- 영상 파일 9회 모두 기존 골든 결과와 일치함.
- 최고 온도는 60.2℃였으며, 온도 때문에 클럭이 떨어지는 현상은 없었음.

### 알게 된 점
- **최종 실행 모드는 MAXN_SUPER로 결정함.**
  - 처리 시간과 Frame Age가 가장 짧음.
  - 기존 성능 측정도 이 모드를 기준으로 진행해 왔음.
- 15W는 전력 절약이 필요한 경우 사용할 수 있음.
  - 카메라 기준 전력 약 21% 절약
  - Frame Age는 6.1ms 증가
  - 그래도 30fps 유지 가능
- 25W는 15W보다 CPU 최고 클럭이 낮았고(1344MHz vs 1497MHz), 영상 기준 프레임당 에너지 소모도 가장 컸음.

현재 프로젝트에서는 응답 속도가 중요하므로 MAXN_SUPER가 가장 적합하다고 판단함.

## 6. 16번 영상의 경고 지연 원인 분석

### 작업 내용
- 16번 충돌 영상에서 경고가 충돌 이후에 발생한 원인을 로그로 분석함.
- 기존 경고 규칙과 새로운 `rawconfirm` 규칙을 비교함.
- `rawconfirm`은 **원시 DANGER가 3프레임 연속 발생하면 경고를 켜는 규칙**임.
- 새 규칙의 코드 문서를 실제 저장소와 비교하고, 프레임별 결과를 확인하는 재생기를 만들어 검증함.

### 원인 분석

기존 경고 규칙에는 두 가지 문제가 있었음.

**첫 번째: 위험 판정을 중복으로 확인함.**

- 원시 DANGER가 발생하면 먼저 안정화 과정을 거침.
- 안정화 후 배너에서 다시 DANGER 횟수를 세기 시작함.
- 따라서 처음 발생한 위험 프레임을 배너 확인 과정에서 활용하지 못해 경고가 늦어짐.

**두 번째: LEAD가 잠깐 사라지면 경고 횟수가 초기화됨.**

- 16번 영상은 74프레임에서 경고 조건을 거의 만족했음.
- 그런데 75~77프레임에서 LEAD가 사라지면서 경고 횟수가 0으로 돌아감.
- 결국 충돌 프레임인 76보다 늦은 **80프레임에서 경고가 발생**함.

### 검증 결과
- 새 규칙 적용 시 첫 경고가 80프레임에서 **74프레임으로 앞당겨질 것으로 재생기에서 확인**함.
- 충돌 76프레임보다 2프레임(약 0.13초) 빠른 시점임.
- 변경 위치 13곳을 코드와 비교했고, x86 빌드 경고는 0개였음.
- 규칙을 껐을 때 기존 결과가 그대로 유지되는지도 확인함.
  - 무작위 입력 600만 회 비교 통과
  - 합성 영상 16개 CSV 결과 일치
- 코드 검토 중 발견한 추가 문제 2개도 수정함.
  - 78~79프레임에서 경고가 잠깐 꺼지는 문제
  - DANGER가 한 프레임 끼어들면 CAUTION 횟수가 초기화되는 문제

### 알게 된 점
- 경고 지연은 단순히 TTC 계산이 늦어서가 아니라 **위험 판정을 여러 번 확인하는 구조와 LEAD 추적이 끊기는 문제**가 겹쳐 발생했음.
- 골든 MD5 비교에 사용하는 `_frames.csv`에는 배너 정보가 없었음.
- 따라서 앞으로 경고 규칙을 수정할 때는 `_banner.csv`까지 확인해야 함.

수정한 `rawconfirm`을 최종 규칙 조합에 추가하면 총 12개 규칙이 됨. Jetson에서 실제로 적용하고 평가하는 작업은 10/9에 진행할 예정임.
