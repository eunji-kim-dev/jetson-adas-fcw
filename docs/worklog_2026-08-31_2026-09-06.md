### 1. x86 Baseline 5회 측정
**작업 내용**
- 8/30에 만든 Harness로 x86 baseline을 측정함
- 처음에는 저녁 8시에 돌렸는데 실행 시간이 회차마다 313 ~ 571초로 제각각이었음
  - 5회 다 PASS였고 MD5도 전부 같았지만 속도 변동폭이 70.6%로 8/27(12.9%)보다 훨씬 컸음
- 원인을 찾으려고 r01을 100프레임 단위로 잘라서 봄
  - 앞부분과 중간은 336 ~ 581 ms인데 마지막 250프레임만 283 ms로 떨어짐
  - 발열이면 뒤로 갈수록 느려져야 하는데 반대 모양이라 발열은 아님
  - 항목별로 보니 추론 시간만 2배가 되고 전처리·후처리는 15% 정도만 늘었음
  - 다른 프로그램이 CPU를 쓰다가 중간에 끝난 것으로 보임
- 측정하는 동안 브라우저로 ChatGPT와 Claude를 쓰고 있었음. 이게 원인이었던 것으로 판단함
- 1차 결과는 baseline으로 쓸 수 없다고 보고 세션을 삭제함
- 밤 9시 47분에 브라우저를 다 끄고 절전을 해제한 뒤 켜둔 채로 다시 측정함
- 측정 전에 재빌드함
  - rebase 때문에 바이너리에 박힌 커밋 해시가 원격에 없는 해시로 남아 있었음

**측정 조건**

**검증 결과**
- 5회 모두 PASS, MD5 5회 전부 `a0006c4a16dbe3f69c178fbc5c1b6b8e`
- 측정 구간 뒤 20%(frame 1005-1252) p50

```text

```

- 변동폭 1.8%. 8/27의 3.4%보다 좋음
- 전체 p50은 216 ~ 375 ms로 여전히 흔들림
  - r02가 앞부분에서 느렸다가 뒤 구간에서는 다른 회차와 같아짐
  - r03부터는 처음부터 안정적이었음
- FCW 판단 결과는 5회 완전히 같음
  - LEAD 6구간, 유지 중앙값 0.85초, 짧은 구간 비율 0.750, TTC 발생률 0.380
- `results/baseline_x86_20260831_summary.csv`, `results/baseline_x86_20260831_env.txt`로 저장함
  - 세션 결과와 아카이브는 `.gitignore` 대상이라 로컬에만 둠

**알게 된 점**
- 브라우저도 배경 프로그램임. 배경 작업이 없다고 생각했는데 브라우저가 CPU를 쓰고 있었음
- 느려졌을 때 어느 항목이 느려졌는지 보면 원인을 좁힐 수 있음
  - 추론만 늘어나면 CPU 경합, 전부 같이 늘어나면 다른 문제
  - 추론은 코어를 전부 쓰기 때문에 코어를 뺏기면 바로 느려짐
- warmup 15프레임은 너무 짧음. r02는 1000프레임이 지나서야 안정됨
  - warmup 값을 바꾸면 golden MD5가 깨지므로 그대로 두고, 대신 뒤 20% 구간을 따로 봄
- 전체 p50과 뒤 20% p50은 다른 숫자임
  - 전체는 71.4%, 뒤 20%는 1.8%
  - Jetson과 비교할 때는 뒤 20% 값을 써야 함
- 속도가 1.7배 차이 나도 FCW 판단은 한 프레임도 달라지지 않음
- x86에서 4.4 FPS라 30 FPS 실시간은 안 됨. Jetson에서는 TensorRT를 써야 함

## 2026-09-06

### 1. Harness Jetson 대응
**작업 내용**
- 계획서 다시 보다가 Harness에 빠진 게 두 개 있었음
  - Power Mode가 `ac_balanced`로 고정돼 있어서 Jetson에서는 상수를 고쳐야 함
  - 계획서에 nvpmodel, jetson_clocks, 온도 기록한다고 적었는데 코드에는 없었음
- Power Mode를 `nvpmodel -q`에서 읽어오게 바꿈
  - 인자로 받을까 했는데 사람이 치면 틀려도 모름. 장비에서 읽는 게 맞다고 봄
  - nvpmodel 없으면 `ac_balanced`. x86은 이쪽으로 감
  - 어디서 읽었는지도 같이 찍고 Manifest에 남김
- Run 전후로 장비 상태를 `device_before.txt`, `device_after.txt`에 남기게 함
  - nvpmodel, jetson_clocks, 온도, CPU 클럭, loadavg, 메모리
  - 없으면 `NOT FOUND` / `N/A`로 적고 넘어감. 진단 스크립트랑 같은 방식
  - 장비 상태를 확인하는 시간은 성능 측정 시간에 포함되지 않도록, 실행 전후에 따로 기록함

**검증 결과**
- x86에서 Harness 1회 실행 → PASS, 기존 MD5와 일치
- Power Mode는 `ac_balanced (default)`로 정상 처리됨
- `device_before.txt`에 nvpmodel, jetson_clocks는 `NOT FOUND`, 온도랑 CPU 클럭은 `N/A`
  - WSL2는 온도랑 클럭을 안 보여줌
  - loadavg랑 메모리는 실제 값 나옴

**알게 된 점**
- 사람이 치는 값은 틀려도 확인할 방법이 없음
  - Jetson에서 실제로는 7W인데 15W라고 치면 로그에 그대로 남음
  - 장비에서 읽으면 이런 일이 없음
- loadavg(CPU가 얼마나 바쁜지 보는 값) 남겨두면 나중에 쓸모 있을 것 같음
  - 8/31에 브라우저 때문에 느렸던 것도 이 값 있었으면 바로 알았을 듯
