### 3. 원거리 Crop을 288×640으로 실행할 수 있도록 수정

**작업 내용**
- 기존 원거리 Crop 추론은 Full 추론과 같은 640×640 입력을 썼음
- Crop만 288×640으로 줄였을 때 속도와 검출 결과가 얼마나 달라지는지 비교하기 위해 구조를 수정함
- Crop 추론에 별도 모델과 입력 크기를 지정할 수 있는 옵션을 추가함

- 실행 결과에 사용한 Crop 모델과 입력 크기를 기록하도록 `run_summary.json`을 확장함
- 구조는 Full 추론 640×640 + Crop 추론 640×640 또는 288×640 선택으로 바뀜

**검증 결과**
- 옵션을 안 쓰면 기존 x86·Jetson 골든 결과와 모두 동일함
- 288×640 옵션을 쓰면 별도 TensorRT 엔진이 정상 생성됨
- 288×640 출력 텐서는 `[1, 84, 3780]`으로 확인함. 640×640의 8400개보다 후처리 대상이 줄어듦

**알게 된 점**
- 초기 구현에서 Crop용 백엔드를 만들었지만 실제 추론 코드는 기존 백엔드를 계속 쓰고 있었음
- 수정 후 288×640 결과가 실제로 달라지는 것을 확인함
- 기존 동작은 유지하면서 Crop 추론만 독립적으로 288×640으로 바꿀 수 있게 됨

- 288×640 효과는 Crop 추론 하나가 아니라 Crop 전체 처리 경로에서 나타남

### 5. 640×640과 288×640 검출 결과 비교

**검증 결과**
- x86 `input.mp4`: 전체 1252프레임 중 검출 개수가 다른 프레임 278개(22%)
- 288×640에서 사라진 박스는 대부분 매우 작은 객체였음. 박스 높이 중앙값 15px, 63%가 높이 20px 이하, 57%가 confidence 0.25 이하
- 두 구조에서 모두 검출된 박스는 크기가 거의 같았음. 높이 차 ±1px 이내가 92% 수준
- LEAD ID가 달라진 프레임도 실제로는 같은 차량을 추적하고 있었고 트랙 번호만 달라진 경우가 대부분이었음
- Jetson 평가셋 21개: 총 3150프레임 중 검출 개수가 다른 프레임 632개(20%), `riskLevel`이 달라진 프레임 89개(2.8%)

**알게 된 점**
- 예상보다 검출 개수 차이는 컸음. 하지만 차이 대부분은 작고 confidence가 낮은 객체에서 생김
- 두 구조에서 모두 잡힌 객체의 박스 크기는 거의 같음
- 검출 개수 차이만으로 288×640의 FCW 기능 저하를 판단하기보다 실제 경고 결과를 같이 봐야 함
- `input.mp4`에서 288×640 TTC가 몇 프레임 늦어진 사례는 Crop 검출 실패보다 기존 TTC-P의 박스 높이 민감도가 원인이었음

### 6. FCW 자동 평가기 작성

**작업 내용**
- 21개 영상의 경고 결과를 사람이 직접 확인하지 않고 같은 기준으로 계산하기 위해 자동 평가기를 작성함
- 입력은 각 영상의 `_banner.csv`와 `eval/videos.csv`임
- 실제 경고는 배너의 `DANGER`를 기준으로 판단함
- 충돌 이후 처음 나온 경고는 늦은 경고로 보고 Miss로 처리함
- 경고 선행시간 = (충돌 프레임 − 첫 DANGER 프레임) ÷ FPS
- 충돌 프레임이 확정된 영상과 추정값인 영상을 구분해 결과를 냄
- 여러 실행 결과를 동시에 비교할 수 있게 구성함

**검증 결과**
- 640×640과 288×640을 같은 기준으로 자동 비교할 수 있게 됨

### 7. 현재 FCW 구조의 1차 기능 평가

**검증 결과**
- 640×640 FP16: 경고가 필요한 영상 12개 중 Warning Miss 9개 (늦은 경고 1개 포함). 경고가 필요 없는 영상 9개 중 False Alarm 2개
- 288×640 FP16: Warning Miss 8개, False Alarm 2개
- 04번 영상만 차이가 있었음. 640×640은 Miss, 288×640은 충돌 약 0.87초 전 경고
- 정상적으로 제때 경고한 영상은 02·05·06이고 경고 선행시간은 약 1.3~1.7초임
- Miss 원인 1 — LEAD 선택 실패 6개: 컷인 차량을 끝까지 LEAD로 선택하지 못함, ROI 밖에 있어 대상에서 제외됨, LEAD로 잡힌 시간이 너무 짧음
- Miss 원인 2 — TTC-P 구조 문제 2개: 차량이 급격히 가까워져도 박스 높이 기반 TTC가 충분히 줄지 않음, 차량 박스가 화면 아래에 닿으면 높이 증가가 멈춤
- Miss 원인 3 — 경고 유지 조건 1개: DANGER가 한 프레임 나왔지만 연속 조건을 못 채워 배너가 안 뜸. LEAD ID가 바뀌면 경고 카운터가 초기화되는 영향이 있었음

**알게 된 점**
- 대부분의 Miss는 640×640과 288×640 차이 때문이 아니라 검출 이후 FCW 로직에서 생김
- 주요 병목은 LEAD 선택 → TTC 계산 → 경고 정책 세 단계임
- Crop 입력 크기를 줄여도 현재 주요 FCW 실패 원인은 거의 그대로 남음
- 288×640 적용 여부는 검출 개수 차이 자체보다 속도 개선과 최종 경고 성능을 기준으로 판단하는 것이 맞음

### 8. TTC 개선 작업을 Crop 결정과 분리

**작업 내용**
- Crop 640×640과 288×640 중 어떤 구조를 쓸지를 먼저 결정하기로 함
- 호모그래피 기반 TTC 개선은 별도 작업으로 분리함
- 이유: Crop 입력 크기는 이후 TensorRT와 INT8 최적화 구조에 직접 영향을 주지만, TTC 계산 방식은 엔진 입력 크기와 별개임. 둘을 동시에 바꾸면 속도 차이와 FCW 기능 차이의 원인을 구분하기 어려움
- 먼저 640×640 vs 288×640의 속도와 기능을 비교해 Crop 구조를 확정하고, 이후 호모그래피 기반 거리 추정으로 TTC-P 문제를 개선할 예정임
- 호모그래피 방향: 도로의 기준점으로 호모그래피 행렬을 계산하고, 매 프레임 차량 박스의 아래쪽 접지점을 도로 좌표로 변환한 뒤, 프레임 간 거리 변화로 TTC를 계산하는 방향으로 검토 중임
