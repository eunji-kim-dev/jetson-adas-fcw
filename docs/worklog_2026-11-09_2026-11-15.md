### 1. 텔레칩스 피드백 검토 및 추가 측정 항목 정리

**작업 내용**
- 포트폴리오를 검토한 텔레칩스 실무자에게 답변을 받음
- 답변 6번에서 제시한 **기능 구성, 성능, 결과 검증, 자원 관리, 전력·지속 동작, 개선 근거**의 여섯 항목을 기존 분석 문서와 코드에 대조함
- 여섯 항목 중 네 항목은 기존 자료로 설명할 수 있었으며, 보완이 필요한 부분은 **프로그램 자체의 메모리 사용량과 전력·지속 동작 검증**이었음
- 이에 따라 추가 측정 항목을 다음 네 가지로 정함
  1. 프로그램을 실행하지 않은 상태의 대기 전력
  2. 동일한 카메라 입력 속도인 30 fps 조건에서의 경로별 소비전력
  3. 최종 설정으로 1시간 연속 실행했을 때의 동작 상태
  4. 보드 전체 RAM과 구분한 프로그램 자체의 메모리 사용량

**알게 된 점**
- **기존 실행 시간은 장시간 동작을 판단하기에 짧았음.** 파일 입력은 20~34초, 카메라 입력은 약 30초 동안 실행한 기록이었음. 최고 온도 57.0 °C도 단시간 실행 중의 값이므로, 장시간 실행 후의 온도는 별도로 확인해야 함
- **기존 파일 입력 전력은 처리 속도 조건이 달랐음.** 10.2 / 10.6 / 11.4 W는 서로 다른 처리 속도에서 얻은 값이므로, W 값만으로 동일 처리량에서의 소비전력을 비교하기 어려웠음
- **30 fps 카메라 조건에서도 전력 기록이 일부 빠져 있었음.** CPU 전처리와 GPU v1 경로의 전력을 추가로 측정해야 함
- **기존 RAM 기록은 OS를 포함한 보드 전체 사용량이었음.** 프로그램 자체의 메모리 사용량을 확인하려면 프로세스 단위의 기록이 필요함
- **판정 이후 배너를 그리는 시간은 다시 측정할 필요가 없었음.** 기존 로그에 `output_ms`가 남아 있어 해당 값을 추출하기로 함

### 2. 카메라 자원 사용량·장시간 동작 측정 스크립트 추가

**작업 내용**
- `scripts/camera_soak.sh`를 추가함
- 관련 커밋: `6777d5a`
- 실행 목적에 따라 세 가지 모드로 나눔

| 모드 | 용도 |
|---|---|
| `check` | 전력 모드, 카메라 입력 간격, 골든 결과 확인 |
| `smoke` | 각 측정 구간을 10초씩 실행하여 동작 확인 |
| `run` | 경로별 자원 사용량 비교 및 1시간 연속 실행 |

- `run`의 실행 순서는 다음과 같음
  1. 실행 전 대기 상태 측정: 3분
  2. 네 경로 비교: CPU 전처리 → GPU v1 → GPU v2 → 최종 설정, 각 5분
  3. 최종 설정으로 연속 실행: 1시간
  4. 실행 후 대기 상태 측정: 3분
- 측정 중에는 `tegrastats`를 이용한 **전력·온도·사용률**과 **프로세스 메모리 사용량**을 1초 간격으로 함께 기록하도록 함
- 구간 실행이 실패하거나 멈추면 측정을 자동으로 종료하도록 구성함

**검증 결과**
- 로그 확인 후 입력 예정

| 확인 항목 | 기록 |
|---|---|
| `check` — 전력 모드 | 확인 예정 |
| `check` — 카메라 입력 간격 p50 | 확인 예정 · 단위: ms |
| `check` — 골든 `_frames`·`_banner` 비교 | 확인 예정 |

**알게 된 점**
- 실행 파일에 기록된 커밋은 **빌드 당시의 커밋**이므로, 저장소의 최신 커밋과 다를 수 있음
- 그 사이 실행 파일에 영향을 주는 소스 변경이 없었다면, 커밋이 다르다는 이유만으로 잘못된 빌드라고 볼 수는 없음
- 이번 측정에서는 네 경로를 **동일한 빌드와 12규칙 설정**으로 비교함
- 결과를 확인한 뒤, 빌드와 규칙 조건이 섞여 있던 기존 카메라 비교표를 갱신할 예정임
