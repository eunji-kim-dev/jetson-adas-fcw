**작업 내용**

- 성능 측정 중 결과 영상을 생성하지 않는 `--no-video` 옵션을 추가함
- 두 옵션은 두 프로그램이 공유하는 `RunOptions.hpp`에 추가해서 한 번만 고침

**검증 결과**
- 목표 처리시간 66.7ms가 정상적으로 기록되는 것을 확인함
- 결과 영상 저장을 끄면 영상 파일이 생성되지 않는 것을 확인함
- 기존 옵션을 사용하지 않았을 때는 이전과 동일하게 동작함

**알게 된 점**
- 기존 테스트 영상은 29.97 FPS여서 목표 처리시간이 자동으로 약 33.4ms로 설정되고 있었음
- 프로젝트 목표는 15 FPS이므로 실제 비교 기준은 66.7ms가 되어야 함
- 입력 영상을 바꿔도 평가 기준이 변하지 않도록 목표 처리시간을 별도로 고정할 필요가 있음

**작업 내용**

**검증 결과**

| 항목 | Jetson CPU | x86 PC |

| --- | --- |

**알게 된 점**
- x86과 Jetson은 CPU 구조와 OpenCV 버전이 달라 YOLO 계산 과정에서 연산 순서와 최적화 방식이 달라질 수 있음. 이 때문에 같은 모델과 영상을 사용해도 confidence나 검출 박스가 소수점 또는 1픽셀 정도 차이 날 수 있음
- 실제 비교에서도 같은 차량의 검출 박스 높이가 31px와 32px로 1픽셀만 달랐지만, 기존 TTC-P는 이 차이를 크게 증폭해 6.884초와 inf처럼 전혀 다른 값을 만들었음
- 따라서 문제의 핵심은 x86과 ARM의 차이 자체가 아니라, 기존 TTC-P가 작은 검출 오차에 지나치게 민감한 구조였다는 것임
- 같은 플랫폼과 같은 설정에서 반복 실행할 때는 결과가 동일한지 확인하고, 서로 다른 플랫폼에서는 MD5 완전 일치보다 FCW 경고 여부·미검출·오경보·경고 시점 같은 실제 동작 결과를 비교하는 것이 적절함

### 4. USB 웹캠 입력 확인
**작업 내용**
- 대여받은 USB 웹캠을 Jetson에 연결하고 실제 영상 입력 특성을 확인함
- 지원 해상도, FPS, 영상 형식, 프레임 간격과 프레임 누락 여부를 측정함
- 자동 노출 기능이 실제 FPS에 영향을 주는지도 확인함

**검증 결과**
- 영상 입력 장치는 `/dev/video0`으로 확인됨
- 영상 형식은 YUYV이며 최대 640×480, 30 FPS를 지원함
- 실제 데이터 전송량은 약 18MB/s로 USB 2.0에서 충분히 처리 가능한 수준임
- 자동 노출 상태에서는 실제 약 25 FPS로 동작함
- 자동 노출을 끄자 약 30 FPS로 정상 동작함
- 시작 직후 약 1.3초의 준비 시간이 있었으며 이후에는 프레임 누락 없이 입력됨

**알게 된 점**
- 이 웹캠은 JPEG 압축 영상을 보내지 않기 때문에 JPEG 해제 과정 없이 YUYV 영상을 BGR로 변환하면 됨
- 자동 노출이 켜져 있으면 주변 밝기에 따라 실제 FPS가 달라질 수 있음
- 따라서 성능 측정 전에 자동 노출을 끄는 것이 필요함
- 카메라를 다시 연결하거나 재부팅하면 자동 노출 설정이 초기화되므로 프로그램에서 직접 설정해야 함
- 카메라 입력에서는 단순히 코드가 프레임을 처리하는 시간뿐 아니라, 카메라에서 촬영된 뒤 FCW 판단이 끝날 때까지 걸린 전체 지연시간도 중요함
